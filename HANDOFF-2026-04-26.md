## What was wrong (root cause)

Yesterday's PM session re-authored `index.html` as a v3 composition with **5 scene divs stacked inline** at full canvas, all `class="scene clip"`. This is a non-standard pattern. HF studio's preview-server pipeline doesn't handle it: clicking play renders all-black scenes for everything except the outro (the topmost in DOM stacking).

The HF render-to-MP4 pipeline DOES handle it correctly because it drives both audio and GSAP via its own controller. So the MP4 looked fine, but the studio preview was unusable — and studio preview is the user's iteration loop.

Per `npx hyperframes docs compositions` and the swiss-grid demo (`npx hyperframes init demo --example swiss-grid`), the documented pattern is **nested compositions**: each scene is its own HTML file in `compositions/`, wrapped in `<template id="X-template">`, referenced from root via `<div data-composition-src="compositions/X.html" data-start=N data-duration=M ...>`. The studio runtime is built around this.

## What was fixed today

`work/2026-04-25-1/` was refactored to the documented pattern:

**Root `index.html` (thin):** global CSS, `assets/gsap.min.js`, `__hf` shim, master timeline `window.__timelines["ai-daily"]` registered SYNCHRONOUSLY in `<head>` (so the studio's player probe finds it immediately), `<audio>` element on track 0, and 5 wrapper divs:

```html
<div id="intro-comp"   class="scene-wrap" data-composition-id="intro"   data-composition-src="compositions/intro.html"   data-start="0"      data-duration="14.67" data-track-index="1"></div>
<div id="story-1-comp" class="scene-wrap" data-composition-id="story-1" data-composition-src="compositions/story-1.html" data-start="14.67" data-duration="56.57" data-track-index="1"></div>
<div id="story-2-comp" class="scene-wrap" data-composition-id="story-2" data-composition-src="compositions/story-2.html" data-start="71.24" data-duration="54.31" data-track-index="1"></div>
<div id="story-3-comp" class="scene-wrap" data-composition-id="story-3" data-composition-src="compositions/story-3.html" data-start="125.55" data-duration="50.75" data-track-index="1"></div>
<div id="outro-comp"   class="scene-wrap" data-composition-id="outro"   data-composition-src="compositions/outro.html"   data-start="176.30" data-duration="9.82"  data-track-index="1"></div>
```

Wrappers do **NOT** have `class="clip"` — adding it broke studio player detection (`proof-fix` went red). Instead, scene cross-cuts are driven by GSAP master timeline `tl.set` on wrapper opacity at scene boundaries, registered in a `DOMContentLoaded` handler (the registration is sync; only the DOM-querying tweens are deferred):

```js
window.__timelines = window.__timelines || {};
(function() {
  const tl = gsap.timeline({ paused: true });
  tl.to({}, { duration: 186.12 }, 0);
  window.__timelines['ai-daily'] = tl;     // sync register so studio probe finds it
  document.addEventListener('DOMContentLoaded', () => {
    tl.set('#intro-comp',   { opacity: 0 }, 14.67);
    tl.set('#story-1-comp', { opacity: 1 }, 14.67);
    // ... cross-cuts at each scene boundary
    tl.set('#outro-comp',   { opacity: 1 }, 176.30);
  });
})();
```

**Per-scene `compositions/<id>.html`:** each `<template>`-wrapped, with `data-composition-id`, `data-start="0"`, `data-duration=N`, scene-relative GSAP timeline (subtract scene start from all absolute times) registered as `window.__timelines["scene-id"]`. Beats inside the scene retain `class="clip"` — that level works fine.

**Cleanup:** Removed scaffolding sub-comp files unused by our composition: `captions.html`, `cinematic-zoom.html`, `graphics.html`, `sdf-iris.html`. Sidebar in studio now shows only `index, intro, story-1, story-2, story-3, outro`.
